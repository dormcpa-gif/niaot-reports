# מערכת דוחות ני"ע

MVP: קליטת דוח Activity Statement של Interactive Brokers (IBKR), חילוץ דיבידנדים/ריבית/רווח הון/עמלות, וסיוע בהפקת **נספח עזר** בפורמט תואם לנספח ג' (רווח הון מני"ע) ונספח ד' (הכנסות חו"ל) של טופס 1301 — כולל **דוח הסבר/מעקב** שמקשר כל סכום לשורת המקור בדוח הברוקר.

ראו את מסמך התכנון המלא: `C:\Users\User\.claude\plans\fuzzy-bubbling-catmull.md`

## פריסה (Deployment)

**Frontend**: פרוס ב-Netlify בכתובת http://niaot-reports.netlify.app.

**Backend**: Netlify Functions תומכות רק ב-Node.js, ולכן ה-backend (Python/FastAPI) **לא יכול להיות מאוחסן ב-Netlify** ועדיין דורש אחסון נפרד לפני שהאתר החי יהיה שימושי בפועל מקצה לקצה.

**אימות משתמשים**: כניסה אישית אמיתית לכל עובד/ת (לא סיסמה משותפת) - ראו סעיף "משתמשים והרשאות" למטה.

### חיבור Render (backend)

יש `render.yaml` בשורש הריפו. כדי לחבר:
1. ליצור חשבון Render חינמי (render.com) - **פעולה שהמשתמש צריך לבצע בעצמו**.
2. לחבר את הריפו הזה (GitHub) לפרויקט Render חדש - Render יזהה את `render.yaml` אוטומטית.
3. להגדיר את משתני הסביבה `ADMIN_EMAIL`/`ADMIN_PASSWORD` (למשתמש המנהל הראשון - ראו למטה) ו-`ANTHROPIC_API_KEY` (לתכונת הניתוח המעמיק).
4. לקחת את כתובת ה-URL שRender נותן (למשל `https://niaot-reports-backend.onrender.com`) ולהגדיר אותה כמשתנה `VITE_API_BASE` בהגדרות הסביבה של אתר ה-Netlify, ואז לפרוס מחדש את ה-frontend.

**הערה חשובה**: בתוכנית החינמית של Render מערכת הקבצים **זמנית** - מסד הנתונים SQLite (`backend/data/app.db`, שכולל כעת גם את כל חשבונות המשתמשים, לא רק נתוני לקוחות) נמחק בכל פריסה מחדש ובכל הפעלה מחדש (לאחר כ-15 דקות חוסר פעילות בתוכנית החינמית). זה בסדר לבדיקות, אך **לפני שימוש יומיומי אמיתי על ידי צוות המשרד יש לשדרג לתוכנית בתשלום עם דיסק קבוע**, או לעבור למסד נתונים מנוהל (Postgres) במקום SQLite - אחרת כל חשבונות העובדים נמחקים בשקט ורק משתמש המנהל הראשוני חוזר בכל הפעלה קרה.

## משתמשים והרשאות

כניסה אישית בלבד לכל עובד/ת המשרד - אין יותר סיסמה משותפת אחת. שני תפקידים:
- **מנהל (admin)** - כל מה שעובד רגיל יכול, ובנוסף: יצירת/השבתת משתמשים, איפוס סיסמאות, וצפייה בלוג הפעילות המלא (`/admin/users`, `/admin/activity`).
- **עובד (employee)** - שימוש רגיל במערכת (לקוחות, דוחות, ניתוח AI). כל עובד רואה את כל הלקוחות במערכת (אין הפרדת הרשאות פר-לקוח - התאמה למשרד עם בסיס לקוחות משותף).

**חשבון המנהל הראשון** נוצר אוטומטית בהפעלה הראשונה של השרת ממשתני הסביבה `ADMIN_EMAIL`/`ADMIN_PASSWORD` (ראו `backend/.env.example`) - רק אם טבלת המשתמשים ריקה. מאותה נקודה, מנהלים יוצרים כל משתמש נוסף דרך מסך "ניהול" באפליקציה.

**לוג פעילות**: כל פעולה משמעותית (כניסה, יצירת לקוח, העלאת דוח, שינוי סיווג, הורדת נספח, הרצת ניתוח AI, ניהול משתמשים) נרשמת עם זיהוי המשתמש ושעת הביצוע - לצפייה במסך "לוג פעילות" (מנהלים בלבד), לצורך זיהוי ואיתור תקלות.

**הרשמה**: מנגנון ה-session הוא טוקן אקראי (לא JWT) הנשמר בטבלת `sessions` ב-DB עם תוקף מתחדש של 7 ימים - כך שביטול גישה למשתמש (השבתה) חוסם מיידית גם sessions פעילים קיימים, לא רק כניסות חדשות.

לפריסת עדכון לאתר ה-frontend הקיים ב-Netlify:
```bash
git add -A && git commit -m "..."
```
ואז שימוש בכלי ה-MCP של Netlify (`deploy-site` עם ה-siteId `6d2d642a-907d-4b7b-9825-c4aec51dafaf`), או `netlify deploy --prod` מקומית אם מותקן ה-CLI.

## מה המערכת עושה (ומה לא)

- מחלצת נתונים מדוח IBKR PDF ומסווגת אותם אוטומטית לפי חוקים ברורים בלבד (למשל: דיבידנד רגיל → שדה 462).
- **כל דבר שדורש שיקול דעת מקצועי (מדרגת מס, "בעל מניות מהותי", ניכוי עמלות) מסומן `needs_review` ודורש אישור/עריכה של רו"ח** לפני הפקת הפלט הסופי.
- אינה מגישה שום דבר לרשות המסים — הפלט הוא קובץ Excel עזר בלבד.
- הוספת ברוקרים/מסמכים נוספים דורשת רק פרסר חדש תחת `backend/app/parsers/` (ראו "הרחבה לברוקר/מסמך נוסף" למטה).
- דוחות שאינם בפורמט הצפוי, או חשבונות שמטבע הבסיס שלהם אינו USD, נדחים עם הודעת שגיאה ברורה בזמן ההעלאה — במקום לעבד אותם בשקט ולהפיק מספרים שגויים.

## ניתוח מעמיק (AI) — דוחות מס זרים

תכונה נוספת, נפרדת לגמרי מהפרסרים הדטרמיניסטיים (regex) שמפורטים למעלה: `/analysis` מפעילה מודל שפה (Claude, דרך Anthropic API) על מסמכי מקור שהועלו — 1040/1040-SR/1040-NR, נספחי Schedule (B/D/E/8582/8995/1116/8833), דוחות מדינה, K-1, 1099/Activity Statement וכו' — לפי "פרומפט מערכת" מפורט (`backend/app/resources/tax_analysis_system_prompt.md`) שכולל הכרעות תושבות, כיוון זיכוי מס זר, ייחוס לסלים, מלכודות מוכרות (כיוון קריאת טופס 1116, Wash Sale, מקדמות חצי-שנתיות ועוד) ומיפוי לטופס 1301.

**זה שונה מהותית מהפרסרים למעלה**: אלה מחלצים מספרים בוודאות (regex/מבנה טבלה), בעוד שהכרעות כמו תושבות וכיוון זיכוי דורשות שיפוט אמיתי שרק מודל שפה יכול לנסח טיוטה שלו אליו — **הפלט הוא תמיד טיוטת נייר עבודה בלבד**, לא קביעה סופית, בדיוק כמו ה-`needs_review` בשאר המערכת, רק שכאן זה מובע בפרוזה/JSON ולא בדגל בוליאני.

**דרישות הפעלה**:
- יש להגדיר משתנה סביבה `ANTHROPIC_API_KEY` (מפתח API אישי, מ-console.anthropic.com) - מקומית (`backend/.env`, ראו `.env.example`) ובענן (משתנה סביבה ב-Render). **בלי זה, שאר האפליקציה ממשיכה לעבוד כרגיל - רק `/analysis` תחזיר שגיאה ברורה.**
- **כל הרצה היא קריאת API אמיתית וכרוכה בעלות** (אין תוכנית חינמית) - אין להריץ ניתוחים ללא צורך.
- ניתן לשנות את המודל הנבחר (ברירת מחדל `claude-sonnet-5`) דרך `ANTHROPIC_MODEL`.

**מגבלות ידועות**: אם קובץ שהועלה הוא PDF סרוק ללא שכבת טקסט, המערכת מזהה זאת ומעבירה למודל הערה מפורשת ("לא נמצא טקסט") במקום לשלוח תוכן ריק בשקט. פענוח בלוק ה-JSON מתשובת המודל הוא best-effort - אם המודל לא החזיר JSON תקין, מוצג הסיכום המילולי בלבד עם הודעת שגיאה מפורשת (לא נכשל בשקט).

## זרימת עבודה

1. **העלאה** (`/`) — בחירת/יצירת לקוח, שנת מס, והעלאת PDF של דוח IBKR.
2. **בדיקת סיווג** (`/review/:id`) — טבלה של כל הדיבידנדים/ריבית/רווח הון/עמלות, עם שדה היעד המוצע בנספח ד'/ג' וסימון `needs_review`. ניתן לשנות ולשמור.
3. **הפקת נספח** (`/preview/:id`) — הזנת שער/י המרה דולר→שקל (שער יחיד ליום מוקדם משמש כברירת מחדל לכל השנה, או שערים נקודתיים לפי תאריך), והורדת קובץ Excel עם שלוש לשוניות: נספח ד', נספח ג', והסבר ומעקב.
4. **לקוחות** (`/clients`, `/clients/:id`) — רשימת כל הלקוחות, ולכל לקוח היסטוריית הדוחות שהועלו עבורו (עם קישור ישיר לבדיקת הסיווג ולהפקת הנספח של כל דוח).
5. **ניתוח מעמיק (AI)** (`/analysis`, `/analysis/:id`) — העלאת מסמכי מס זרים (1040/נספחים/K-1/דוחות מדינה/ברוקר) יחד, הרצת ניתוח מבוסס בינה מלאכותית, וצפייה בסיכום מילולי + JSON מובנה (הכרעות תושבות/זיכוי, הכרעות פתוחות, מסמכים חסרים, בקרות הצלבה, מיפוי ל-1301). ראו סעיף "ניתוח מעמיק (AI)" למעלה לפני שימוש.

## מבנה הקוד


## הרחבה לברוקר/מסמך נוסף

1. ממשו מחלקה חדשה תחת `backend/app/parsers/` שמחזירה `NormalizedStatement` (אותם מודלים בדיוק: `Dividend`, `InterestItem`, `Trade`, `FeeItem`).
2. רשמו אותה ב-`_PARSERS` בתוך `backend/app/services/extraction_service.py`.
3. שכבות המיפוי (`mapping/`), השירותים (`services/`) והפלט (`output/`) לא צריכות להשתנות כלל.
